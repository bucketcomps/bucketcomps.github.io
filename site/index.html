field rules
  1. Bring your own data: legally obtained game discs or dumps only.
  2. Zero game assets: no ROMs, keys, firmware, or copyright binaries in Git.
  3. Honest methodology: the binary is evidence; recovered source is a hypothesis.
  4. Receipts over hype: incremental proof beats percentage theater.

methodology

How We Work: Honest Proof

In preservation and decompilation, precision matters. We separate claims into distinct, verifiable categories rather than inflating numbers.

01 // verification

Matched ≠ Verified

A matched function compiles to identical machine instructions. A verified function has also been exercised across runtime inputs, edge cases, and hardware behavior checks.

02 // empirical reality

Real Hardware Grounding

We do not guess at hardware behavior or copy other emulators. When processor signaling or graphics pipelines are ambiguous, we run tests on real retail PS3 consoles.

03 // legal boundary

Clean-Room Boundaries

No copyrighted assets, keys, or proprietary SDK material ever enter our Git trees. Users bring their legally purchased game media, and our tools operate as clean-room interpreters.
